⚡ What's New in v1.7.0: Facebook Expansion (Option 1) & Warning System

Facebook Share Links Resolver (/share/p/ and /share/r/)

Facebook uses database tokens instead of direct post IDs in URLs like https://www.facebook.com/share/p/18V4XJ9abc/. Meta serves an HTML response running XMiBUrlWrapperController JavaScript that prevents traditional HTTP 301/302 redirects.

Option 1 Implementation: CleanLink now spins up a lightweight, sandboxed headless Android WebView on-device with JavaScript enabled. It runs the client-side redirection script in ~1-2 seconds, captures the canonical permalink, and purges all tracking tokens—without third-party API dependencies.

Bonus Config: A dedicated toggle in Protection / Rules > Preferences allows disabling Option 1 at any time (enabled by default).

⚠️ [ RED WARNING ] // FACEBOOK SHARE SHIM EXPANSION FAILED Triggered when a Facebook share link cannot be resolved into a canonical permalink (for example, if the post is private, age-restricted, requires a Facebook login session, or times out). CleanLink strips all query parameters (mibextid, rdid) and alerts the user with an actionable link to the Technical Deep Dive section.
⚠️ [ ORANGE ADVISORY ] // UNEXPANDED OPAQUE SHORTLINK Triggered when generic opaque shorteners (such as bit.ly, t.co, vt.tiktok.com, a.co) cannot be resolved via HTTP redirect traversal (offline or server error). The alert informs the user that opaque tracking telemetry remains encapsulated in the slug itself so they can make an informed sharing decision.
